# AI Development Organization
## Database Design & Data Dictionary V1.0

**Document ID:** ADO-DATA-001  
**Version:** 1.0  
**Database:** PostgreSQL  
**Status:** Initial Baseline

---

## 1. 设计目标

建立统一研发数据中心，支持：

- 多项目管理。
- 多 Agent 管理。
- 多 Worker 管理。
- 任务与工作流。
- Codex Thread 生命周期。
- GitHub 仓库和 PR。
- 审批与权限。
- 文件和交付物。
- 知识库。
- 审计与模型用量。

## 2. 数据分层

### Layer A：Core Data
users、roles、projects、repositories。

### Layer B：Agent Data
agents、agent_versions、skills、agent_runs。

### Layer C：Execution Data
tasks、task_dependencies、workers、workspaces、codex_threads、execution_events。

### Layer D：Delivery Data
approvals、pull_requests、test_results、artifacts、releases。

### Layer E：Knowledge & Audit
knowledge_documents、audit_logs、model_usage。

## 4. 关键数据关系

- Project 1:N Repository
- Project 1:N Task
- Project N:M Agent
- Agent 1:N Agent Run
- Task 1:N Agent Run
- Worker 1:N Agent Run
- Agent Run 1:N Execution Event
- Agent Run 1:N Codex Thread（支持多轮执行）
- Task 1:N Approval
- Task 1:N Artifact
- Task 1:N Test Result

## 5. 数据隔离规则

1. 所有项目业务数据必须有 project_id，GLOBAL 级公共配置除外。
2. 所有 API 必须校验项目成员权限。
3. 数据库启用必要的 Row-Level Security。
4. Worker 只能访问授权项目。
5. 对象存储使用项目级路径和访问策略。
6. 项目知识检索必须带项目过滤条件。
7. 敏感凭证不存入普通业务表。

建议对象存储路径：

/global/
/projects/FITBEST/
/projects/ADO/

## 6. 索引与性能

重点建立：
- tasks(project_id, status)
- tasks(project_id, priority)
- agent_runs(task_id, status)
- execution_events(agent_run_id, sequence_number)
- workers(status, last_heartbeat_at)
- repositories(project_id)
- audit_logs(project_id, created_at)
- model_usage(project_id, created_at)

执行事件量增长后按时间进行分区或归档。

## 7. 数据一致性

- 业务事务由 PostgreSQL 管理。
- 任务下发采用 Transactional Outbox。
- BullMQ 仅承担消息传递，不作为业务事实数据库。
- 消费端必须支持幂等。
- 每个执行事件具有唯一序号。
- 任务状态变化必须留痕。
- Webhook 事件必须去重。

## 8. 数据保留策略

建议初始策略：
- 任务及审批：长期保留。
- 执行事件：按项目策略保留，支持归档。
- Worker 心跳：保留近期明细，历史聚合。
- 日志：根据安全和成本策略保留。
- 文件产物：按项目版本策略保留。
- 密钥：由专门凭证服务管理。

具体保留期限属于部署前待确认事项。

## 9. 数据库验收标准

1. 能够创建两个独立项目。
2. 可以为项目绑定不同仓库。
3. 能够完整记录任务生命周期。
4. 能够查询 Codex Thread 与任务的关系。
5. 可以查询 Worker 执行记录。
6. 能够追踪每次审批。
7. 能够记录测试报告和 PR。
8. 项目隔离测试通过。
9. 数据库迁移可以重复部署。
10. 备份和恢复流程验证通过。

## 10. 设计边界

第一期不要求独立向量数据库，不把所有执行事件存入单个 JSON 字段，不允许业务系统仅依赖模型对话历史维持状态。
