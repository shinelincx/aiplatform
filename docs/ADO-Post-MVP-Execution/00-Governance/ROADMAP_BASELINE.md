# Frozen Post-MVP Roadmap Baseline V1.0

**基线类型：规划；冻结范围：方向、阶段顺序、阶段完成条件及安全原则；实施状态：全部未知。** 源自《Codex SDK 用途》对话中的 Post-MVP Evolution Roadmap V1.0；用户要求作为冻结基线使用。后续变更必须通过书面变更提案与人工批准，不覆盖此版本。

## 已确认方向与架构基线
- 云端统一控制，本地/独立机器执行；从第一天支持多项目；GitHub 为统一代码仓库；Codex SDK 为主要编码执行引擎；通用 Agent 框架承担专业分析与协作。Fitbest 第一试点，ADO 第二试点。关键操作由人类最终审批。
- 两项目共享经过批准的岗位与通用技能，但数据、代码、知识、密钥和执行权限严格隔离。ADO 研发数据与 Fitbest 业务数据不混用；不同数据库或严格隔离的 schema、凭证及访问权限。项目级授权与工作目录隔离。
- 基础架构设计采用云控制面+分布式 Worker、模块化单体优先，Worker 独立部署；设计选型包括 Next.js/React/TypeScript、NestJS、PostgreSQL、Redis/BullMQ、S3 兼容存储、Node/TypeScript Worker、Git worktree、Docker、REST/WebSocket、GitHub Actions。它们是设计基线，不是现有代码或已配置服务的证明；实施前核对原始五项文件和仓库。Worker 主动认证连接；Codex SDK 与通用模型路由为不同接口，不将 Codex Thread 当通用模型会话。
- 保持 Fitbest PRD V1.0、已确认需求、既有架构和版本管理；仅依据已批准范围选试点。对话提及独立 AI 健身 Agent、训练计划、训练数据闭环、长期记忆、知识库及安全规则，亦提及 API/MCP、真实语音、移动构建：均为方向或待核实的范围，不构成当前功能存在或允许新增的证明。若业务、健康或安全规则缺失，停止相关实现并请求批准文件与业务负责人决策。

| 阶段 | 基线目标及完成条件 | 建议周期 | 建议版本 |
|---|---|---|---|
| MVP prerequisite | 基础执行闭环验收；证据未核实 | 未知 | MVP 1.0 |
| P1 | Fitbest 至少一个真实功能端到端研发、测试、人工验收 | 2–4 周 | ADO 1.1 |
| P2 | 不同 Agent 实例按统一标准重复完成同类任务；岗位、技能、设计、质量与知识治理 | 3–5 周 | ADO 1.2 |
| P3 | 自身 Agent 团队组织、开发、测试和交付至少一次平台升级；双项目及故障恢复验证 | 2–4 周 | ADO 1.3 |
| P4 | 新增项目无需重建底层 Agent/Worker 系统；多项目隔离和资源成本管理 | 4–8 周 | ADO 2.0 |
| P5 | 持续发现问题、提出有证据的建议、在授权范围内受控执行 | 持续 | ADO 2.5 |

周期是初步估计，不是排期承诺；阶段可局部准备并行，但不能跳过验收门。建议版本号不覆盖实际 Git tags/releases。各阶段指标、完成证据与签署规则见 `05-Acceptance/PHASE_GATES.md`。横向治理覆盖 Agent 生命周期、知识来源、项目归档、质量、成本与审计。

## 未确认
