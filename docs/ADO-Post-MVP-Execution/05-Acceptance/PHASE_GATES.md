# Phase Gates

阶段门由 Project Director 汇总、独立 QA 核实、指定人类负责人签署。必须记录范围、日期、负责人、依据、实际结果、证据链接、未通过项、整改和批准；未指定审批人则 OPEN，不推定通过。前一门未通过禁止进入下一阶段实施。

| 门 | 必要验收证据 |
|---|---|
| MVP | 对照原始 MVP 验收标准逐项记录证据及人类验收；不能用此规划包证明完成。 |
| P1 | 一个真实功能完成端到端研发、测试、人工业务验收；需求/验收覆盖、任务记录、变更追溯、自动测试报告完整率各 100%；人工验收通过率 ≥80%；未授权主分支和生产操作均 0。业务逻辑不符即不通过。分母及计算方法先在验收计划确认，记录实际数量；无样本不计通过。 |
| P2 | 岗位标准明确；不同实例重复完成同类任务；技能版本/审核/回滚、设计可检索、自动质量门、独立 QA、知识隔离均可验证。 |
| P3 | 至少一次自身团队组织并交付的真实平台升级；双项目并行、独立 Worker、故障安全恢复、自动测试和回滚，人工审批及隔离证据。 |
| P4 | 多项目并行及权限隔离，Worker 动态增退、岗位/技能分配、项目成本统计、冲突处理；新项目复用底层能力的实测证据。 |
| P5 | 定期发现问题，有证据的建议和风险分类；预授权低风险隔离执行、完整审计、人工暂停与撤销均验证；生产自主操作关闭。 |

## 交付质量门
G1 需求：批准范围、验收标准与追踪；G2 设计：架构、接口、UI、数据与风险审查；G3 开发：代码审查、适用静态检查和测试；G4 交付：独立 QA、PR、人类审批、发布及回滚检查。按任务类型裁剪不适用项并记录原因和负责人；安全及人工审批不可裁掉。质量门与阶段门是两套独立判断。
