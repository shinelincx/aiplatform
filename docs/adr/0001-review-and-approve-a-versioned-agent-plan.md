# Agent 规划以复核后的方案版本送审

状态为已接受，决定日期为 2026-11-24。

ADO 当前会在角色依次生成输出后送审，人工答案可以随原方案一起交给 Worker。我们决定在送审前把专业评审和人工决定落实到同一份方案，以便项目所有者审阅实际要执行的范围、行为和验收条件。为控制等待和返工，只评审适用的领域，并在方案修订后复核受影响的部分。

## 规划与评审

- 产品经理维护需求、范围和可验证的验收条件。架构师评审可行性、技术风险和实施步骤。任务改变用户流程、页面交互、界面状态或设计规范时，UI/UX 参与评审。项目总监协调分歧和依赖，并检查方案是否具备送审条件。
- 评审所需的文档、代码、测试和设计资料通过项目授权范围内的只读访问核对。引用仓库证据时，记录所用提交及文件位置。缺失的证据会影响范围、权限、可行性或验收时，暂停送审。次要缺口记录假设及验证方式。
- 影响范围、权限、用户行为或验收的待决策事项，在选项、建议及影响明确后尽早交给项目所有者。受决定影响的工作等待答复，独立工作可以继续。答案落实到需求、验收条件、实施步骤或设计后，由相关角色复核受影响的内容，再提交修订版本。

## 审批与执行

项目所有者批准具体的方案版本，派发使用同一版本。执行前复核审批范围、提交和环境。审批绑定的目标发生变化时，按现行审批政策重新批准。
