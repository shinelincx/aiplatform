## 页面层级和操作

| 层级 | 用户目标与主要操作 | 次要操作与上下文 |
| --- | --- | --- |
| 工作台 → 项目 | 侧栏切换项目，项目概览显示任务、审批、Worker 和执行指标 | 概览提醒直达对应任务。项目切换回到所选项目的工作台。编辑、成员和归档仍在概览内 |
| 项目 → 研发任务列表 | 选择任务或在有写权限的项目内打开创建表单 | 已批准需求来源独立加载，登记和从新任务撤下沿用活跃项目所有者条件。绑定仓库后的 Agent 规划仍可使用手工需求 |
| 研发任务 → 详情 | 根据既有状态与角色呈现计划审批、派发、运行、执行审批与按驳回意见修订 | 次要入口包括编辑、取消、归档及任务记录。返回列表保留项目并定位到原任务链接。基线列表没有筛选、排序控件或分页。需求来源操作保留当前项目及已选任务 |
| 项目 → 管理与运维 | 仓库绑定及检查配置、Agent 与 Skill 配置、Worker 凭证和授权、项目用量与审计 | 工作台导航直接定位现有面板。Worker 列表保留在线状态和仅注册与心跳的能力信息。运维页保留对应项目及返回入口 |

导航负责定位，列表负责项目内任务选择，详情负责呈现任务状态和条件操作。表单保留现有输入约束和 API 校验。提交按钮和结果提示可在任务、执行和需求来源之间复用。需求来源区域拥有自己的读取、重试和可选来源状态，业务权限及状态流转继续由既有面板条件和 API 控制。

| 设计原则 | 可检查的流程与反馈 |
| --- | --- |
| 自然 | 从项目切换到概览、任务列表和详情，使用返回链接定位刚查看的任务 |
| 确定性 | 区分需求来源加载中、服务端确认的空列表、会话失效、权限不足、服务异常、提交中和提交结果。派发成功提示指向执行状态 |
| 意义感 | 项目主视图提供研发任务入口，创建入口位于任务列表后；详情显示当前状态和相应操作，撤下按钮作为次要操作 |
| 生长性 | 项目导航聚合既有面板，需求来源读取独立隔离，通用提交和反馈组件不持有业务规则 |

## 本机视觉融合复验

在独立工作树应用本机视觉改动后，三方应用归档补丁 `17f9b5b7f8ed5cefb213d34a4da010b4462bf045f23889245338e27a4f6d8367`。在工作台和任务区的冲突中保留顶部导航、三列布局、四项概览指标和首屏任务入口，接入独立需求区域及操作反馈。键盘打开任务详情时聚焦详情区，返回时定位原任务。往返运维页保留所选任务。

- Chromium 使用受控 API 响应，在 1440×1024 验证三列布局、四项指标和任务行首屏可见，在 390×844 验证无横向溢出和任务列表、详情的键盘焦点往返。
- 浏览器复验需求读取在 401、403、500 时显示对应反馈并保留任务列表，服务端确认的空列表显示空状态。成功登记或撤回后保持区域展开，显示对应成功提示。
- 浏览器复验运维往返保留任务，任务详情读取失败时仍显示前次操作成功提示，只读角色没有创建任务或登记需求的入口。
- 当前浏览器覆盖使用隔离测试账号和受控响应。预发布的派发、候选审批、Worker 凭证与心跳应在实际控制面验收。
